# V2 设计：可信的图纸，可控的方案

日期：2026-11-25
来源：`试用体验.docx`（试用反馈）＋ 现有实现（`docs/contract.md`、`index.html`、`server.mjs`、`deploy/public-jobs.mjs`）
状态：待评审（rev 3，已吸收两轮独立工程评审）

**rev 3 增补**：确定性检查改为客户端即时计算；编辑合法性定为"拖得动、导不出"；尺寸链增加 `axis` / `chain` 分组；提示词预览由服务端回传；补齐验收样本依赖与预算对比口径。

**rev 2 修订摘要**：项目层改用 IndexedDB 并定义完整迁移；墙窗检查改为"围护边界 + 洞口衔接"；尺寸模型加入稳定 ID、量测面、固定侧与联动传播；校核层加入原图对照与标定；任务层明确后端能力；Plan V2 改为稳定 ID 的对象模型；效果图根因与验收改写；多方案数据归属明确；CAD 结论修正；交付拆为 V2.0 / V2.1。

## 1. 问题重述

试用反馈包含二十余条意见，分布在识别、操控、功能、项目管理、体感五处。逐条看很散，归纳后只有一条主线：

> **用户不敢信，也改不了。**

尺寸、弧墙、飘窗、墙/窗混淆四类错误，全部缺少人工纠正手段；识别慢且没有反馈，用户会误以为卡死并刷新页面，把一个可恢复的过程变成一次失败。相比之下，家具库偏少、助手能力、吊顶缺失属于"上限"问题，不影响用户是否敢把方案继续做下去。

第二条线索是**方案是活的**：同一个户型要做多版方案、来回切换比较、改价、导出给施工方。当前"一个项目 = 一份方案 + 一个存档点"，撑不住真实工作方式。

### 1.1 需要纠正的判断

- 反馈猜测"弧墙识别错误与 Web 3D 引擎有关"。实际不是：`Plan` 契约中弧墙/弧窗（`ArcBand`）已是一等对象，3D 由其生成。缺的是识别侧的弧段输出与确定性校验。
- 反馈提出"用 codex 导出 DWG"。原生 DWG 写入并非只有商业 SDK 一条路：GNU LibreDWG 具备写入能力，但支持程度随版本波动，工程上不宜作为承诺。V2 导出 **DXF**（开放文本格式，CAD、施工图软件均可直接打开），DWG 作为后续可选项由外部工具转换，不写进界面承诺。
- 现有项目列表**已经使用 IndexedDB**（`interior-projects-v1<scope>`），只迁移 localStorage 会丢项目。规格按 IndexedDB 设计。

## 2. 设计原则

1. **可修正优先于更聪明。** AI 的输出视为初稿；用户的每一次修正都必须有入口、有反馈、可撤销。准确率提升是加分项，不是前提。
2. **单一数据源。** 手工修正写回 `Plan` / `State` 本身，不引入覆盖层。2D、3D、导出、效果图共用同一份几何。
3. **不新增模式。** 除"校核"（本质是 2D 画布上的一个图层与选中态）外，不新增全屏界面、不新增右侧页签。能力长在现有画布、属性面板和项目列表上。
4. **进度即信任。** 任何超过 2 秒的 AI 操作都必须有阶段名、已用时间和"可以离开"的承诺；不允许出现无反馈的等待。承诺由后端任务支撑，不由前端文案支撑。
5. **估算必须可见。** AI 推测的字段带标记，用户确认后消失。用户不该在不知情的情况下继承一个猜出来的尺寸。

**非目标**：做完整 CAD；做施工图；做云端协作与账号体系；重写 3D 引擎。

**反目标**（即使功能跑通也算失败）：
- 用户仍需在别处（CAD、酷家乐）完成尺寸核对。
- 手工修正后 2D/3D 出现新的不一致。
- 引入第二套"修正数据"，导出时丢失。
- 为覆盖反馈而堆出十个新面板。

---

## 3. 方案总览：六层归属

每条反馈都必须落到下面某一层，不新增第七层。

| 层 | 职责 | 对应反馈 |
|---|---|---|
| 识别层 | 图纸 → Plan 的准确性与证据 | 尺寸、弧墙、飘窗、墙窗混淆、2D/3D 不一致 |
| 校核层 | 用户纠正识别结果 | 尺寸手动调整、墙/窗/飘窗手工改、主动权 |
| 任务层 | 长任务的进度与可离开 | 识别/对话/效果图慢、误以为卡死 |
| 项目层 | 项目 → 多方案 → 比较 | 重命名、排序、方案管理、方案对比 |
| 视图层 | 3D 漫游的连续性 | 站立点、记住视角、转向平滑 |
| 交付层 | 预算、导出、效果图、天花 | 改价、DWG/DXF、渲染参数、吊顶 |

## 4. 识别层

识别端只做三件硬事，其余交给校核层。原则：**宁可给出标注清楚的近似值，也不要静默地错。**

### 4.1 尺寸链驱动的标定

`plan-import.md` 增加强制步骤：

1. 先提取图中全部尺寸标注，形成尺寸链（总尺寸、分段尺寸、墙厚、门窗洞口）。
2. 用尺寸链建立图像坐标 → 毫米的映射；总尺寸优先，分段尺寸交叉校验，不一致时以总尺寸为准并记录偏差。
3. **尺寸界线对齐**：明确每条尺寸对应的是墙轴线、外沿还是内沿；外墙尺寸默认取外边界，内部分户墙取轴线，房间净尺寸取内沿。输出中写明采用了哪一种。
4. 每一段直墙必须能追溯到至少一条尺寸依据；无法追溯的墙标为估算。
5. 识别结果保留**原图标注值**（`drawingValue`），与按几何反算的模型值分开存储，供校核对照（见 5.2）。

### 4.2 飘窗专项规则

飘窗按"看得见的线"识别，不靠猜测：

- 三条边有窗线、室内侧有窗台线、尺寸链出现 600/800 一类的窗台深度 → 判定为飘窗。
- 弧形转角飘窗：窗线在转角处连续弯曲 → 按弧窗输出，切点由两侧直线与弧线交接处确定。
- 飘窗输出为两部分：`rooms` 中 `counted:false` 的房间轮廓（内沿）＋ `wins` 中的窗段。缺一不可。
- 识别不确定时仍输出两段，但在 `explanation` 与对应对象的 `source` 中标记"估算"。

### 4.3 弧墙与玻璃转角

- 图纸上出现连续曲率的墙线/玻璃线，必须输出弧墙/弧窗；直线与弧的切点、半径、扫角在输出中给出。
- 禁止用一串阶梯矩形近似弧（当前近似方式是 2D/3D 观感错误的主要来源）。
- 复核提示词（`plan-verify.md`）增加弧段专项：检查相邻直段与弧段是否在端点衔接、是否重复铺设墙体、弯曲方向与原图是否一致。

### 4.4 确定性检查（重写）

**关键事实**：现有模型在洞口处会断开墙体（`plan-import.md` §3.5），因此"窗洞必须被单段实墙完整包含"的检查必然误报——样例 125-C 的 12 扇直窗中满足该条件的为 0。检查规则改为围绕**围护边界（boundary run）**：

1. **洞口衔接**：每扇窗/门/推拉门必须位于一条共线的墙体序列上，且洞口两端分别与两侧墙段的端边对齐（容差 1 mm），厚度与偏移一致。
2. **洞口重叠**：同一围护边界上的门、窗、推拉门互不重叠。
3. **房间贴边**：房间多边形的每条边应落在墙体内沿或指定的外沿上（容差 2 mm），不得穿过墙体实体。
4. **尺寸链**：同一方向相邻尺寸之和与总尺寸、模型几何的偏差 > 5 mm 时报警，并定位到差在哪一段。
5. **弧段衔接**：弧段端点与相邻直墙端点距离 > 1 mm 时报警；弧半径与厚度关系非法时报警。
6. **飘窗完整性**：`counted:false` 的房间必须在外沿上存在对应窗段。

**墙与窗的类别**不能仅凭几何判定：实墙即使被错认成窗，几何也可能完全自洽。检查只报告"疑似类别冲突"（该墙段没有窗符号证据但存在窗几何，或反之），由用户在校核层确认，不自动改写。

**运行位置与归属**：六条检查是纯几何运算，在**客户端**随每次编辑即时重算（对象数量在百级，耗时毫秒级）；服务端只在识别与复核完成时给出初始结果并存入任务，供导入流程展示。忽略记录存于方案（`state.checkIgnores: string[]`），不随任务过期；离线与 `file://` 模式下检查照常运行。这样用户修墙后角标即时更新，不依赖服务端往返。

### 4.5 Plan V2 数据模型

`Plan.version` 当前固定为 `1`，直接写 `Plan & {version:2}` 会产生类型冲突。V2 明确定义 V1/V2 两套类型，读取 V1 时迁移，写入一律 V2。

```ts
type Source = 'drawing' | 'ai' | 'user'

type PlanV1 = { version: 1, /* 现有结构，元组形式 */ }

type PlanV2 = {
  version: 2
  name: string
  bounds: { x:number, y:number, w:number, h:number }
  walls: (WallSeg | WallArc)[]          // 对象化，带稳定 id
  wins:  (WinSeg | WinArc)[]            // 窗属性内联，不再按下标旁挂
  doors: (Door & { id:string, source?:Source })[]
  slides: (Slide & { id:string, source?:Source })[]
  rooms: (Room & { ceiling?: Ceiling, source?:Source })[]
  materials: Record<string, Material>
  dims: Dim[]
}

type WallSeg = { id:string, rect:Rect, kind:WallKind, height?:number, source:Source }
type WallArc = { id:string, from:Point, to:Point, sweep:number, thickness:number,
                 kind:WallKind, height?:number, source:Source }

type WinSeg = { id:string, rect:Rect, sill?:number, h?:number,
                style?:'casement'|'sliding'|'fixed'|'floor'|'bay', source:Source }
type WinArc = { id:string, from:Point, to:Point, sweep:number, thickness:number,
                sill?:number, h?:number, style?:WinStyle, source:Source }

type Ceiling = { h?:number, drops?:{rect:Rect, depth:number}[],
                 cove?:'none'|'perimeter', box?:boolean }

type Dim = {
  id: string
  source: Source
  from: DimAnchor
  to: DimAnchor
  offset: number                 // 尺寸线相对 from→to 连线的偏移
  drawingValue?: number          // 原图标注值，mm
  axis: 'x' | 'y'                // 量测方向，用于成链与求和
  chain?: string                 // 同一尺寸链的分组键；缺省按 axis + 共线推断
  locked: 'from' | 'to' | 'none' // 固定哪一端；数值修改时移动另一端
  note?: string                  // 如「外墙外沿」
}

type DimAnchor =
  | { kind:'wall', id:string, face:'axis'|'outer'|'inner'|'left'|'right', point:Point }
  | { kind:'room', id:string, edge:number, face:'inner', point:Point }
```

**迁移规则**：V1 元组按数组顺序生成稳定 ID，同一 ID 在本次迁移中固定；门的 `rect`、铰链等字段原样保留；窗的几何保持，`sill/h/style` 置空并标 `source:'ai'`。迁移只发生一次，写回 V2。

**Why 对象化而不是旁挂 `winInfo`**：按下标关联的窗属性在删除前面一扇窗后必然串位；稳定 ID 是尺寸引用、撤销、AI 补丁和 DXF 导出的共同前提。

## 5. 校核层（V2 的核心）

### 5.1 定位与入口

校核不是新编辑器，是 2D 画布上的一个**图层 + 选中态 + 属性面板分区**。入口两处：

- 导入结果页「校核图纸」按钮（替代当前的直接"打开新项目"为主行动）。
- 项目列表中任一项目的「校核」。

### 5.2 画布：原图对照是第一块内容

只画尺寸线不足以核对。校核画布必须同时提供原图参照：

- **分屏**：左原图、右模型，缩放与平移同步；窄屏退化为上下分屏。
- **叠加**：原图以 30% 不透明度铺在模型下方，可一键切换；提供"仅显示墙线"模式减少干扰。
- **两点标定**：在原图上点两个已知尺寸的端点并输入标注值，重算全图比例。用于扫描件、跳过识别误差直接校准。
- **数值对照**：选中尺寸时同时显示「原图 10700 / 模型 11000 / 差 +300」，并高亮该尺寸取自哪对墙面。这是发现"两条尺寸线取了不同墙面"的唯一可靠方式。
- 尺寸链以细线 + 数字绘制在墙体两侧：图纸/AI 来源为中性灰，用户新增为深色，估算项带 `≈`。
- 检查未通过的对象带角标；点击循环定位。
- 顶部一条极窄状态带替代弹窗：`3 处待确认 · 2 处估算 · 下一步`。不遮挡画布。

### 5.3 对象与可编辑属性

全部复用现有属性面板，选中结构对象时替换为结构分区。

| 对象 | 可改 | 行为 |
|---|---|---|
| 直墙 | 类型 e/b/n/low、厚度、高度、端点拖动、转为弧墙 | 拖动端点时附着门窗随动；相邻墙不自动延伸 |
| 弧墙 | 半径、起止角、厚度、高度、类型、转为直墙 | 拖动切点改变半径；厚度 ≥ 直径时即时拒绝 |
| 窗 | 位置、宽度、窗台高、窗高、样式、转为实墙 | 样式影响 3D 与效果图提示词 |
| 实墙开窗 | 在选中墙段上"开窗"，按墙厚/高度生成窗 | 新窗 `source:'user'` |
| 门 | 位置、宽度、开向、铰链侧、是否入户门 | 与现有门字段一一对应 |
| 飘窗 | 轮廓顶点、窗台高、是否计面积、是否带垫 | 作为房间编辑，面积即时更新 |
| 新增飘窗 | 选房间外沿 → 生成"不计面积房间 + 三面窗段" | 反馈建议的"飘窗模块"，一次成型 |
| 房间 | 名称、顶点、地面材质、计面积 | 顶点编辑只做冲突提示，不强约束 |
| 尺寸 | 新增、删除、拖动、改数值 | 改数值 = 移动所关联的墙（见 5.4） |
| 天花 | 见 8.4 | 同类面板 |

**候选机制**：用户新增的墙/窗/门/尺寸进入同一数组并带 `source:'user'`，不另存。AI 修正（复核、对话）沿用现有 `editScene` 路径，天然可撤销。

### 5.3.1 编辑合法性：拖得动，导不出

编辑过程中**不硬阻断**拖动：窗被拖到墙外、墙端点错位都允许暂时存在，以红角标标出，不弹窗。只有产生退化几何的操作即时拒绝：弧墙厚度 ≥ 直径、墙长为 0、门扇长度为 0——那是不可逆的数据损坏，不是可修复的语义错误。

- **保存**：始终成功，非法状态随方案保存，避免用户丢工作。
- **导出 DXF / 生成效果图**：以确认框列出未解决项，用户可选择"仍然导出/生成"。
- **退出校核**：提示一次未解决项，不阻断。

这条规则替代此前的"窗洞不在墙上时保存被拒绝"：即时拒绝会与"编辑即写回、没有保存按钮"的交互冲突，也会让拖动中途被卡住。

### 5.4 尺寸与模型的联动（重写）

- **派生尺寸**：任意两个结构面之间的距离可即时显示（悬停或选中时），永远与模型一致，不存储。
- **标注尺寸**：`Dim` 用 `DimAnchor` 记录两端各自依附的墙/房间边与量测面（轴线/外沿/内沿/左右面），而不是两个裸坐标。拖动尺寸两端时吸附到面。
- **改尺寸 = 改模型**：
  1. 用户输入目标值；
  2. 若 `locked` 指定了固定端，移动另一端；`none` 时若两端都可能移动（如两片平行墙），先让用户点选"移动哪一面"，不猜测；
  3. 平移被引用墙段；与其相接的垂直墙段同步延长/缩短；
  4. 墙上的门窗随墙移动；房间多边形中落在该墙面上的边同步更新；
  5. 面积、预算随之重算；
  6. 整条链作为一个撤销步骤。
- **尺寸链校验**：同 `chain` 或同 `axis` 且共线的相邻尺寸自动成组；分组之和与总尺寸不符时，状态带提示差值，并高亮差在哪一段。成组是数据字段优先、几何推断兜底，避免同方向不同墙线的尺寸被错误相加。
- **原图值保留**：`drawingValue` 不因改模型而清除，校核界面持续显示"图上 / 现在"的差；用户可一键恢复为图上值。

### 5.5 估算标记与转正

- `source` 为 `ai` 或 `drawing` 的字段在校核界面标出来源；用户编辑后置为 `user`。
- 状态带的"2 处估算"可点击，逐个跳到对应对象。
- 关闭校核时若仍有估算项，仅提示一次，不阻断。

### 5.6 撤销与保存

- 校核中的所有修改进入现有撤销栈，Ctrl+Z 逐步回退。
- 校核完成即写回当前方案，不需要"应用"按钮；"完成校核"只是退出图层。
- 识别原图、识别快照（只读 `basePlan`）、校核后的方案三者分开保存，支持"恢复识别结果"。

## 6. 任务层：进度与可离开

### 6.1 统一任务原语（含后端能力）

前端任务条不是弹窗，出现在对应入口附近，并在项目列表/右侧页签留可回来的入口：

```
[阶段名]  ·  已用 1:24  ·  通常 1–3 分钟  ·  可以离开，完成后在这里通知
```

- 阶段名是动词短语，来自 SSE `status` 或本地阶段枚举；长阶段用不确定进度条 + 计时器，不显示伪造百分比。
- 计时器每秒跳动是"没卡死"的最强信号。
- 任务完成、失败、可复核时在项目列表对应条目显示状态点，页面标题加未读标记。

**"可以离开"必须由后端兑现，当前不具备**：

- 本地 `/api/chat` 与 `/api/render` 在连接关闭时直接 `interrupt()`；公网任务 3 分钟无轮询即被终止（`POLL_LEASE`），15 分钟总时限。
- V2 改为统一后台任务：`POST /api/jobs/<kind>` 返回 `jobId`；任务与浏览器连接解耦，结果落盘；前端刷新后按 `jobId` 重新轮询。
- 本地任务的保留期：运行中任务在断开后继续执行；终态结果保留 ≥ 30 分钟供恢复。
- 公网：轮询租期延长到 ≥ 10 分钟，或用页面可见性心跳续租；总时限保持并在 UI 上写明。
- **任务归属**：每个任务记录 `projectId`、`schemeId`、`baseRevision`。完成时若当前方案已变化，结果进入"待确认"，不自动应用（沿用现有补丁拦截逻辑，扩展到跨方案）。
- **去重**：提交带幂等键（方案 + 操作 + 参数摘要），重复点击复用同一任务。

### 6.2 各任务的阶段

| 任务 | 阶段 |
|---|---|
| 图纸识别 | 上传 → 读取图纸 → 识别结构 → 识别家具 → 自检 → 复核（可选）→ 完成 |
| 对话改方案 | 理解 → 生成修改 → 应用 |
| 效果图 | 截取视角 → 生成 → 保存 |

阶段由服务端 `status` 事件驱动；服务端未给出时前端按已用时间给出"仍在识别结构"的兜底文案，不伪造已完成。

### 6.3 渲染按钮选中态

反馈"按钮点了之后实际选上了，但是没有保持选中状态"的根因是 **CSS 覆盖**，不是状态同步：`.chips .btn{background:#fff;color:var(--muted)}`（375 行）与 `.btn.on{background:var(--ink)}`（33 行）权重相同且在后者之后，选中色被覆盖。修复为 `#render .chips .btn.on` 的显式规则；同时补一条自测：切换风格 → 切页签 → 返回 → 仍选中。

## 7. 项目层：项目 → 方案

### 7.1 存储与迁移（重写）

**沿用现有 IndexedDB**，不引入第二套存储：

- 现有库：`interior-projects-v1<scope>`，每个项目一行（`snapshot` 等）。升级到 version 2，新增 `schemes` 对象仓（以 `id` 为主键，`projectId` 建索引），`projects` 行增加 `name`、`order`、`basePlan`、`sourceTaskId`、`budget`、`viewpoints`。
- 迁移：逐个现有行生成一个"默认方案"，把 `snapshot` 拆为 `plan` + `state`，保留家具、效果图记录、`sourceTaskId` 与复核关联；`basePlan` 取当前方案的结构快照。迁移在 `onupgradeneeded` 中以事务完成，失败时保留旧库并提示导出。
- localStorage 只保留：当前项目指针、语言、UI 偏好。现有 `interior-plan-v1` / `interior-state-v1` 仅在库为空时作为兜底导入一次。
- **项目导出升级为 v3**：包含项目元数据、全部方案（几何 + 状态 + 效果图记录）、预算、视角；导入接受 v1/v2/v3。现有"导出项目"只导出当前方案，需同步修改。

### 7.2 数据归属（明确共享与隔离）

| 数据 | 归属 | 规则 |
|---|---|---|
| 识别原图、识别快照 | 项目 | 只读；支持"恢复识别结果" |
| 校核结果 | 方案 | 校核写回当前方案，不影响其他方案 |
| 新建方案 | 方案 | 默认复制**最近确认（校核完成）的方案**；没有则复制 `basePlan` |
| 材料单价 | 项目默认 + 方案覆盖 | 项目提供默认报价；方案可覆盖单价；未覆盖时跟随项目 |
| 视角/站立点 | 方案 | 结构变更（墙/房间几何变化）后标记"结构已变更"，保留坐标但进入时提示 |
| 效果图记录 | 方案 | 方案复制时复制记录，删除方案不删图片文件（保留 30 天） |

- **对比口径**：预算按各方案的有效单价（方案覆盖优先，否则项目默认）计算；材料集合不同时在对比页脚注明，不做跨材料折算。面积、房间数、家具数直接取方案自身几何。

### 7.3 交互

- 项目列表支持**重命名**（就地编辑）、**拖拽排序**（`order`）、按更新时间/名称排序切换。
- 方案级操作：新建、重命名、复制、删除、设为对比基准。
- **一次识别、多个方案**：识别成功后自动创建"方案一"。
- **对比**：并排显示两个方案的 2D 缩略图（同一缩放与原点）＋关键指标差异（面积、房间数、家具数、预算）。不做 3D 对比与逐家具 diff。

## 8. 交付层

### 8.1 预算可改价

- 材料单价存于项目 `budget.prices`，方案可覆盖；修改即时重算房间与总价。
- 只开放单价，不开放面积公式（面积必须与几何一致）。
- 显示"按当前单价估算"，避免被当成合同价。

### 8.2 DXF 导出

- 新增 `exportDxf()`：输出 ASCII DXF（R2000），图层 `WALL`、`WINDOW`、`DOOR`、`ROOM`、`DIM`、`FURN`、`CEILING`。
- 墙用闭合多段线；弧墙/弧窗用 `ARC` 或带 bulge 的多段线，保留真实曲率，不退化为折线。
- 家具用块引用；尺寸用 `DIMENSION`，退化时用线 + 文本。
- 单位 mm，原点与 Plan 一致；导出时翻转 y 轴以符合 CAD 习惯。
- 不导出：效果图、材质贴图、灯位。
- 界面文案写"DXF（CAD 可打开）"；DWG 说明可用 CAD 另存，或后续接入 LibreDWG（写入支持随版本变化，不作为承诺）。

### 8.3 效果图

- 风格：每个风格模板改为结构化提示（配色、材质、照明、家具轮廓、负向约束），生成前展示"本次将使用的描述"。
- **提示词预览由服务端回传**：`/api/render` 在生成前发送 `{"type":"prompt","text":"..."}`，前端只负责显示，不保存模板副本——模板唯一存放在 `prompts/render.md`，避免两处数据源漂移。验收直接比对展示文本与服务端实际使用的文本。
- 补充描述：优先级高于风格模板，固定在提示词前部；空描述时不注入风格默认词。
- 记录风格、描述、机位，支持"同机位同描述重生成"。
- 修复选中态（6.3，CSS 根因）。

### 8.4 天花（四件套）

- 每房间可设：平顶层高、若干矩形局部下沉（带深度）、沿边灯槽开关、窗帘盒开关。
- 2D：独立"天花"图层（默认关闭），显示下沉区与灯槽虚线；不参与墙体选择。
- 3D：室内/漫游显示；剖切视图显示截面；鸟瞰默认隐藏。
- 效果图：提示词注入天花描述。
- 不做：异形曲面、多层跌级、灯位与回路、风口、施工节点。

### 8.5 家具库（V2.2，仅预留结构）

- 家具库支持二级分类与每类"更多"入口；数据结构支持 `subcat`，内容扩容单独进行。
- 不新增几何生成器。

## 9. 视图层：漫游

- **站立点**：3D 顶视/鸟瞰下点击地面 → "站在这里"，进入漫游从该点开始；也可从房间清单选房间。
- **记住视角**：每个方案保存最近一次漫游的站立点与朝向；可命名保存多个视角。结构变更后标记过期。
- **平滑转向**：鼠标与触屏转向加阻尼（约 80–120 ms 收敛），降低灵敏度；保留无阻尼选项。
- 室内视角与漫游切换保持现有裁切逻辑。

## 11. 验收标准（修订）

精度分来源，不搞一刀切：

| 来源 | 尺寸/几何精度 |
|---|---|
| 矢量图纸（DXF/PDF 矢量） | 与标注偏差 ≤ 3 mm；弧半径偏差 ≤ 5 mm |
| 位图/扫描件 | 与标注偏差 ≤ 10 mm；比例误差在两点标定后 ≤ 1% |
| 估算项（无标注） | 不设数值门槛，必须带 `≈` 标记并在校核状态带列出 |

| 反馈 | 验收 |
|---|---|
| 识别慢、像卡死 | 任务启动 500 ms 内出现阶段名与计时器；编辑不阻塞；刷新后按 jobId 恢复；关闭标签页不终止本地任务 |
| 弧墙/玻璃识别错 | 弧墙图纸导入后存在弧墙且端点衔接；3D 无阶梯状墙面；弧窗验收检查端点、弯曲方向、窗台高、玻璃接缝，不只看包围盒 |
| 尺寸识别错 | 每条尺寸显示「原图值 / 模型值 / 差值」；尺寸线可追溯到所依附的墙面 |
| 内部分户墙没有尺寸 | 可添加分段尺寸；改数值后墙体移动、接缝与房间轮廓同步、面积重算、撤销一步；两墙都可能移动时必须先让用户选 |
| 2D/3D 对不上 | 确定性检查无未解释冲突；同一对象 2D/3D 包围盒一致 |
| 飘窗识别错 | 典型与弧形转角飘窗均输出房间（`counted:false`）+ 窗段；可用"新增飘窗"模块手工补 |
| 墙显示成窗 | 可把窗转实墙、在实墙上开窗；类别冲突只提示不自动改 |
| 漫游总回起点 | 退出再进入回到上次站立点；可从任意位置"站在这里" |
| 转向晃 | 转向收敛 ≤ 120 ms，无跳变 |
| 效果图按钮不回显 | 切换页签、刷新后风格仍选中；自测覆盖 CSS 规则 |
| 风格差别小 | 同一参考图、"白天自然光 → 傍晚暖光"必须可见变化，同时机位与布局不变 |
| 补充描述无效 | 描述出现在最终提示词前部；同机位下描述变化导致对应元素变化 |
| 预算不能改价 | 改单价即时重算；方案覆盖与项目默认的优先级正确 |
| 吊顶无法设计 | 四件套可设、2D 可见、3D 可见、效果图提示词包含 |
| 项目分不清 | 可重命名、可拖拽排序；旧项目迁移后全部可见 |
| 一项目多方案 | 一次识别后新建 3 个方案；方案 A 的单价覆盖不影响 B；对比可并排 |
| 导出 DWG | 导出 DXF 可被 CAD 打开；用带弧形飘窗的户型做回读，实测半径、洞口宽度与修改后净尺寸；图层与单位正确 |
| 项目导出 | v3 导出包含全部方案；删除后重新导入完整恢复 |
| 测试样本 | `tests/fixtures/plans/37200-villa/` 已放入第一套真实样本（弧形转角露台、弧形飘窗、双电梯与楼梯），含 `expected.json` 与 `check.mjs` 粗检；仍需补位图扫描件与独立弧墙样本 |
| 非法状态 | 拖窗出墙不被阻断、保存成功、红角标；导出与生成效果图时弹出确认；退化几何操作被即时拒绝 |

## 12. 风险与待复现项

- **改尺寸的传播语义**：只移动被引用墙段及其接缝、门窗、相邻房间边；不做全图约束求解。复杂户型可能需要多次修改，接受这一点换取可预测性。
- **IndexedDB 迁移**：`onupgradeneeded` 事务失败会阻塞启动；迁移前先做只读导出，失败时回退旧库并提示。
- **确定性检查误报**：贴边、弧段衔接可能产生噪声；阈值集中配置，允许单条忽略并记录。
- **公网任务时限**：延长租期会增加服务端常驻任务数，需要与 `MAX_ACTIVE` 一起调。
- **DXF 保真度**：中文文本样式与编码需实测；曲线用 ARC/bulge，不用折线。
- **识别准确率仍是上限**：V2 不承诺"识别即正确"，承诺"错了能改、改得动、改完一致"。
- **待复现**：试用截图中 2D/3D 偏差的具体成因，需要用当时的原图与识别结果跑一遍，确认是房间多边形与墙体矛盾还是家具高度/构件问题。
- **验收样本**：第一套真实样本（37200 弧形露台户型）已入库，`check.mjs` 可做尺寸链、弧段、飘窗与房间数量的冒烟检查，但逐条尺寸仍需人工在原图上核对。还缺位图扫描件与独立弧墙户型各一套。

- 云端账号、多人协作、版本历史（超出单机存储的边界）。

- 第 3 方素材库接入与版权采购。
- AI 助手能力升级（按反馈排序，放在 V2.2）。
