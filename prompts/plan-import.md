# 户型图纸解析（plan-import）

工作目录里有用户上传的户型资料：图片（JPG / PNG / WebP / 截图 / 扫描件）、PDF（多页时找含户型的那一页）、CAD 导出（DXF / DWG 转出的图片、打印稿或文本）、以及可能已经是 Plan 结构的 JSON、纯文字说明等，**格式不固定**。

读取请求附带的图像和工作目录中的资料，自行识别文件格式。识别户型、家具和图纸上明确画出的构件，输出结构字段和 `furniture`。

图纸标定、结构读取和家具识别使用同一份原图。需要放大检查时可读取本地文件。

## 1. 坐标、单位与尺寸链标定

### 1.1 坐标与单位

- 全部长度单位是 **mm**。
- 2D 坐标系：x 向右，y **向下**；原点可自选，通常取户型左上角 `(0, 0)`。
- 直墙、直窗、门和推拉门使用轴对齐矩形。斜直墙可用矩形近似，并在说明里注明。
- 弧墙、弧形窗和房间圆角使用圆弧字段。**禁止**用阶梯矩形、45° 折线或一串小直段近似弧。
- 家具按同一映射从图中的相对位置落位。

### 1.2 尺寸链标定（强制，先于任何几何输出）

识别结构前必须完成下面的步骤，顺序不得调换；结论写进 `explanation`。

1. **提取全部标注**：通读图上横向、纵向的每一条尺寸线，记下数值与两端尺寸界线的落点；同时记墙厚标注（240 / 200 / 120）、门窗洞口宽度或编号、层高与窗台高、半径（R）与角度标注。同一方向、共线的标注按图中顺序组成一条尺寸链。
2. **总尺寸优先**：每个方向先找总尺寸，用「总尺寸 ÷ 两端尺寸界线间的图像距离」得到 mm/px；x、y 分别标定。没有总尺寸时用最长分段之和代替，并在说明里写「无总尺寸」。
3. **分段交叉校验**：同一尺寸链的分段之和与总尺寸比较。差值 ≤ 5 mm 视为一致；超过 5 mm 时以**总尺寸**为准重算比例，在说明里写出「哪条链、差多少 mm」，并把可疑分段标为估算（`source:"ai"`）。分段之间互相矛盾时同样以总尺寸为准。
4. **明确量测面**：每条尺寸都要说明量的是墙轴线、外沿还是内沿。默认外墙尺寸取外边界 `outer`，内部分户墙 / 承重墙取轴线 `axis`，房间净尺寸取内沿 `inner`，洞口尺寸取洞口两侧的墙面 `left` / `right`。文字说明、`dims[].note` 与几何必须一致，不得混用。
5. **逐墙上账**：每段直墙、每个弧段至少能追溯到一条尺寸或一个半径标注。可追溯的写 `source:"drawing"`；只能按比例量算、对称推断或用常见值补齐的写 `source:"ai"`。无法追溯的墙一律按估算输出，不要静默给出精确值。
6. **保留原值**：`drawingValue` 一律写图上读数（整数 mm），不写按几何反算的模型值；图上给的是分段就记分段。模型值与图上值的差异由校核界面负责显示，识别端只负责如实记录。

### 字段说明

- `version`：固定为 `2`。直墙、直窗、门、推拉门、房间都是对象，**不再使用元组**；每个对象必须带 `id` 与 `source`。
- `bounds`：2D 世界范围（含墙厚），四周可留 240mm 余量。
- `walls`：直墙 `{ id, rect, kind, height?, source }`，`rect` 坐标**已含墙厚**（矩形就是墙体本身，不是中心线）。`kind`：`e` 外墙、`b` 承重墙、`n` 非承重墙、`low` 矮墙。
- `wins`：窗。直窗 `{ id, rect, sill?, h?, style?, source }`，`rect` 是窗洞矩形，贴在墙上，不要跨出墙体外。`sill` 窗台离地高度、`h` 窗洞高度（mm）；`style` 取 `casement` 平开、`sliding` 推拉、`fixed` 固定或玻璃幕、`floor` 落地、`bay` 飘窗。
  - 默认 `sill: 900`、`h: 1500`；落地窗 `sill: 0`、`h` 取过梁到地面；飘窗按 §2.3；厨房台面窗可 `sill: 1100`。
  - 按窗扇符号判断样式：平开有开启弧线，推拉为两条错位平行线，连续玻璃无框按 `fixed`。没有符号依据时按洞口特征推断，并在说明里列出推断项。
  - `sill + h` 不超过层高（默认 2800）。
- `doors`：平开门（门洞 + 门扇），字段在原有基础上加 `id` 与 `source`。
  - `rect`：门洞矩形 `[x0, y0, x1, y1]`，落在墙体上。
  - `h`：**铰点坐标** `[x, y]`，取门洞矩形的一个角。
  - `c`：**关门时门扇的方向单位向量**，从铰点指向关门状态的门扇末端；必须沿门洞长边，取值 `[1,0]` `[-1,0]` `[0,1]` `[0,-1]`。
  - `o`：**开门方向单位向量**，从铰点指向开门状态的门扇末端；与 `c` 垂直，取值同上（`c·o = 0`）。
  - `len`：门扇长度（mm），等于门洞长边（例如 800–900）；`rect` 的短边只是墙厚（如 240），不要拿短边当 `len`。
  - 入户门加 `"entry": true`；一户型最多一个。
- `slides`：推拉门。`{ id, rect, v, source }`；`v` 为 `true` 表示门洞**竖向**（长边沿 y，门扇沿 y 方向推拉），`false` 表示横向。
- `rooms`：房间多边形。
  - `poly`：顶点数组 `[[x,y], ...]`，**至少 3 个点**，首尾**不重复**，不要自交；同一房间的顶点按**视觉顺时针**排列（y 向下时鞋带公式面积为正）。
  - `arcs` 可用于有圆角的房间、阳台或露台。弧段登记为 `{"edge":i,"sweep":90}`，从 `poly[i]` 到 `poly[(i+1)%poly.length]`，每条边最多一条弧。不需要在 `poly` 里放中间采样点。室内轮廓使用墙或玻璃内缘的切点，室外相邻地面使用外缘的切点，室内外轮廓和墙窗中心线共用圆心。
  - `id`：英文小写、不重复；`name`：中文。
  - `mat`：`materials` 里的键；`at` 是标签位置，可省略（服务端取质心）。
  - 飘窗等不计面积的房间加 `"counted": false`。
  - **至少要有 1 个房间**，否则页面会拒绝加载。
- `materials`：键名尽量用固定 8 种：`wood`、`walnut`、`tile800`、`tile600`、`marble`、`antislip`、`terrazzo`、`carpet`；每项 `{ name, price, sw }`（`sw` 是色块 `#rrggbb`，`price` 是每平米单价，认不出就给合理默认）。
- `dims`：尺寸链，见 §2.2。
- `furniture`：见下方家具识别。

### 2.1 稳定 id 与 source

- 同一数组内唯一、英文小写加数字、不复用：墙 `w1`、`w2`…（直墙与弧墙共用一个序号，按输出顺序递增）；窗 `win1`、`win2`…；门 `d1`、`d2`…；推拉门 `s1`、`s2`…；尺寸 `dim1`、`dim2`…。房间沿用语义 id（`living`、`master`、`kitchen`、`bath1`、`bay1`…）。
- `dims` 的 `from.id` / `to.id` 引用这些 id，不再写裸坐标。id 里不要夹带坐标或尺寸，识别完成后不得改写。
- `source`：`drawing` 表示几何或数值可由图面标注直接确定；`ai` 表示按比例量算、对称推断或常见值补齐。导入只输出这两种，**不要写 `user`**。
- 只有样式、窗台高之类的属性靠推断而几何明确时，对象 `source` 仍按几何来源写，把推断项集中写进 `explanation`。

### 2.2 dims：图上尺寸链

图面上每一条可见尺寸线（含总尺寸）输出一条 `Dim`，不合并、不省略。由几何反算而非图面标注的尺寸**不要**写成 `dims`。

```json
{ "id": "dim1", "source": "drawing",
  "from": { "kind": "wall", "id": "w1", "face": "outer", "point": [0, -240] },
  "to":   { "kind": "wall", "id": "w1", "face": "outer", "point": [8240, -240] },
  "offset": 1200, "axis": "x", "chain": "x-1", "locked": "none",
  "note": "外墙外沿", "drawingValue": 8240 }
```

- `from` / `to`：两端锚点，二选一：
  - 墙面：`{ kind:"wall", id, face:"axis"|"outer"|"inner"|"left"|"right", point:[x,y] }`，取值对应墙的轴线、外沿、内沿、左端面、右端面；`point` 必须落在所量的那个面上。
  - 房间边：`{ kind:"room", id, edge:i, face:"inner", point:[x,y] }`，`edge` 与 `rooms[].arcs` 的口径一致，从零起算。
- `offset`：尺寸线相对 `from → to` 连线的偏移（mm），按图中尺寸线在墙体外侧的相对位置给正值；与连线重合时写 `0`。
- `axis`：`"x"` 或 `"y"`，量测方向，用于成链求和（不是尺寸线的摆放方向）。
- `chain`：同一尺寸链的分组键。横向自上而下为 `x-1`、`x-2`…，纵向自左向右为 `y-1`、`y-2`…；局部链可用 `x-1-客厅` 这类后缀区分。
- `locked`：`"none"`。固定端由用户在校核时指定，识别不要把某端锁死。
- `note`：量测面文字，如「外墙外沿」「分户墙轴线」「主卧净宽」「飘窗窗台深度 600」。
- `drawingValue`：图上读数（整数 mm），必填；读的是分段就写分段，不要换算成总尺寸。

### 2.3 飘窗与弧形转角

按「看得见的线」判定，不靠猜测。凸出外墙轮廓、正面与两侧三条边有窗线、室内侧有与墙平行的窗台线 → 判定为飘窗；尺寸链中的 600 / 800 一类窗台深度或「飘窗 / 凸窗」文字用于确认判定并补全 `sill`。窗线与窗台线清楚、只缺深度标注时，仍按飘窗输出，`sill` 按 500 估算并标 `source:"ai"`；只有深度标注而窗线不清时，按飘窗候选输出，同样标 `source:"ai"` 并在说明里写「飘窗按估算」。

输出**两段，缺一不可**：

1. `rooms` 中一条 `counted:false` 的房间轮廓，`poly` 取**内沿**（室内看到的窗台内侧 / 墙内沿），名称如「主卧飘窗」。
2. `wins` 中沿外沿输出窗段，三面都要有，不能只给正面：直边用 `{ rect, ... }`，弧形转角用弧窗；`style:"bay"`。

- `sill` 取窗台线高度：有标注按标注（常见 400–600），无依据按 500 估算；`h` 取洞口高度，无标注按 1500。
- **弧形转角飘窗**：窗线在转角连续弯曲 → 按弧窗输出。`from` / `to` 取两侧直线与弧线的**切点**，`sweep` 按 y 向下规则（顺时针为正）；半径取 R 标注，或由弦长与 `sweep` 反算 `r = 弦长 ÷ (2·sin(|sweep|/2))`，把切点、半径、扫角写进 `explanation`。房间轮廓在该边写 `arcs:[{edge:i,sweep}]`，与窗段共用圆心，室内取内缘切点、室外取外缘切点。
- 不得用两段 45° 直窗或阶梯矩形代替弧形转角。
- 判定不确定时**仍然输出房间 + 窗段两段**，两者 `source:"ai"`，并在 `explanation` 中写明「飘窗按估算」。缺任何一段都算识别失败。

### 2.4 弧墙与弧窗

- 原图出现连续曲率的墙线或玻璃线，必须输出独立的圆弧对象；弯曲起点即直段的终点。
- 弧墙写法：`{ id, from, to, sweep, thickness, kind, height?, source }`；弧窗写法：`{ id, from, to, sweep, thickness, sill?, h?, style?, source }`。
  - `from`、`to` 是圆弧**中心线**的起止点（mm），取与两侧直线的切点；`thickness` 是截面总厚度（mm），必须小于直径。
  - `sweep` 是从起点到终点扫过的有符号圆心角，绝对值为 0.5–180 度。在 y 向下的坐标里，顺时针为正，逆时针为负；交换起点和终点时反转符号。
- **端点衔接**：弧的 `from` / `to` 与相邻直墙、直窗的端点一致（误差 ≤ 1 mm），不留缝、不重叠；弧的包围盒内不要再铺直墙或直窗，也不要重复铺设洞口。转角处厚度、`kind`、`height` 与相邻直段一致，不突变。
- **弯曲方向**：以弦的中垂线判断弧凸向哪一侧，与图面核对后再定 `sweep` 的正负；符号写反会得到镜像弧，属于硬错误。
- 透明玻璃连续转角归入 `wins`（弧窗）。下方有窗台或矮墙时，矮墙输出为 `kind:"low"` 的弧墙，窗段单独输出，两者共用圆心与切点。
- 半径有标注按标注；没有则按弦长与扫角反算，并在 `explanation` 中列出每个弧段的半径、扫角与切点。

## 3. 识别规则

1. 优先使用图纸上标注的尺寸；没有标注时，用常见门宽 800–900 mm、600 地砖、墙厚等推算比例，并在说明里写清假设。先完成 §1.2 的尺寸链标定，再画几何。
2. 墙厚默认：外墙 240 mm、内墙 120 mm、矮墙 100 mm。图纸有标注时以标注为准。
3. 房间 id 用英文小写（`living`、`master`、`kitchen`、`bath1`…），不要重复。
4. 房间名称用中文（客厅、主卧、厨房…）。
5. 门洞、窗洞要落在围护结构上，两侧的实墙在洞口边缘断开。保留连贯的玻璃转角和相邻地面的圆弧轮廓；半径根据图纸标注或原图比例量算。
6. 每段墙、窗、门、房间都必须带稳定 `id` 与 `source`；无法追溯到标注的对象标 `source:"ai"`，不要伪装成精确值。
7. 缺少的信息给**合理默认值**（门朝内开、房间地面用 `tile800`、无窗等），不要留空字段，也不要编造不存在的房间。
8. 材料无法判断时：卧室/客厅用 `wood`，厨卫/阳台用 `tile800` 或 `antislip`，并在说明里注明。
9. 若上传的是 Plan JSON 或带 `plan` 和 `state` 的项目 JSON：已是 V2 的原样保留 `id` 与 `source`，只补缺失字段；V1 元组按数组顺序生成 `w1…` / `win1…` / `d1…` / `s1…`，窗的 `sill` / `h` / `style` 留空并标 `source:"ai"`。保留已有家具和构件的坐标、尺寸、角度、`handedness`、`topShape`、`height` 及 `parts`。项目 JSON 的家具和构件来自 `state.furniture`，输出时放在和结构字段同一级的 `furniture`。

### 家具识别

逐个房间检查原图。餐桌、每把画出的餐椅、边几、橱柜台面、台面上清楚可辨的水槽或灶具，各按轮廓单独记录。保留原图明确画出的组合叠放关系，例如茶几在地毯上。多个资料画出同一件物体时只记录一次。固定柜体可以按所在房间和轮廓匹配家具库中的对应柜类。无法区分是物体、门窗符号还是注释的图形可省略。

优先采用家具明确标注的尺寸，其余按标定比例从图面量算。选用对应的家具库类型，尺寸采用量算结果。若轮廓局部缺失，以能识别的轮廓和同图同类物体估算，并在中文说明中指出近似项。若原图只画了空房间，输出空数组。

输出前逐个比对局部原图和家具组合。放大客餐厅等布置密集的区域，核对以下关系，同时沿用整张图纸的坐标标定。

- 用最近的墙、窗、柜体等作参照，检查家具中心在原图的相对位置、家具前后方向、成组家具的间距和数量。例如，转角沙发的短段应位于原图指定的一侧，茶几在沙发两段围出的空区，餐椅逐把对照餐桌和靠背方向。
- 按看得见的外轮廓核对 L 形、圆形、椭圆和矩形，通过结构字段表达。模型库确实缺少对应轮廓时，可按下节建模。只把具有独立实物轮廓的符号识别成家具。
- 检查实物轮廓与墙体和家具的重叠，L 形沙发只检查两段实体占地。保留有原图依据的套叠圆桌、茶几压地毯、台面嵌装和餐椅收进餐桌等关系。看不清的形状或关系写进中文摘要，供用户在打开方案前核对。

家具库类型如下。

- 卧室：`bed` 床、`crib` 婴儿床、`nightstand` 床头柜、`wardrobe` 衣柜、`dresser` 梳妆台、`desk` 书桌、`chair` 椅子、`bookshelf` 书架、`baycushion` 飘窗垫。
- 客厅：`sofa` 直排沙发、`cornersofa` 转角沙发、`armchair` 单人沙发或扶手椅、`beanbag` 懒人沙发、`coffeetable` 茶几、`sidetable` 边几、`tvstand` 电视柜、`rug` 地毯、`shoecab` 鞋柜或玄关柜、`floorlamp` 落地灯、`plant` 绿植。
- 餐厨：`table` 桌、`roundtable` 圆桌、`island` 岛台、`barstool` 吧椅、`counter` 橱柜台面、`stove` 灶具、`ksink` 水槽、`fridge` 冰箱、`cabinet` 储物柜或餐边柜。
- 卫浴：`toilet` 马桶、`vanity` 浴室柜或洗手台、`shower` 淋浴房、`bathtub` 浴缸、`washer` 洗衣机、`waterheater` 热水器。
- 家电：`tv` 电视、`aircon` 柜机空调、`acwall` 挂机空调、`dishwasher` 洗碗机、`ovencol` 蒸烤箱高柜、`dryer` 烘干机、`purifier` 空气净化器。
- 书房与休闲：`officechair` 办公椅、`piano` 钢琴、`treadmill` 跑步机。

### 图纸构件和家具库缺项

楼梯、端景、壁龛、异形展示柜等有清晰图示或标注却无对应家具库模型的物体，用 `type: "component"` 输出。按原图整体轮廓确定 `cx,cy,w,d,rot`，通过 `parts` 描述占地和立体形状。一件构件用一条记录，组成部分留在同一个 `parts` 中。

- 每个部件是 `{ "shape": "box", "x": 0, "z": 0, "w": 1, "d": 1, "y": 0, "h": 800 }`。其中 `x,z` 是相对构件中心的局部横向和纵向比例，范围 `[-0.5,0.5]`，`w,d` 是占整体宽深的比例，范围 `(0,1]`。`y` 为底面标高，`h` 为高度，单位均为 mm。可选 `rot` 为部件自身的顺时针角度，可选 `color` 为色值。每件最多 48 个部件。
- `box` 表示板、柜、台和平台等矩形体。`cylinder` 表示圆形或椭圆柱体。`stairs` 表示平行踏步线的直梯段，另填整数 `steps`（1–32）。`rot: 0` 时沿局部 `-z` 到 `+z` 上行。
- `winder` 表示围绕内角转向的扇形踏步。每级由 `pivot` 与外边界上相邻两个 `edges` 点围成。点坐标都相对这个部件自己的宽深归一化，范围 `[-0.5,0.5]`。沿上升方向排列外边界点，可沿矩形外边的拐角转折，`edges` 有 `steps + 1` 个点，`steps` 为 2–32。比如内角在上边中央、从左到右折返四级时，`pivot: [0,-0.5]`，`edges: [[-0.5,-0.5],[-0.5,0.5],[0,0.5],[0.5,0.5],[0.5,-0.5]]`。
- 通过踏步线、箭头和平台标记判定楼梯走向。细看转角：如果多条斜线向同一内角汇聚，应按各斜线对应的外边界端点创建 `winder`。水平平台用 `box`，等距平行踏步用 `stairs`。各梯段的 `h` 为该段高差，后段从前段顶点标高继续，段间在平面上衔接。楼梯间仍可另有房间轮廓。
- 端景从文字标注和图形确认。用图中轮廓还原占地，以板、台、陈设等组合表达。一处构件的高度、材质或内部构造无法从原图读取时，在说明中注明按估算建模。

## 4. 识别失败 / 不完整时的兜底

按以下顺序处理，不要硬编造：

1. **能认出户型轮廓和房间**：按图输出完整 Plan，把按图估算的圆弧尺寸、比例或其他近似写进说明。
2. **只能认出部分**（例如只有外墙轮廓、只有房间名、只有尺寸标注）：输出**最合理的完整 Plan**（至少 1 个房间，墙 / 地面给默认值），并在说明里逐条列出「哪些是推测」。
3. **是照片 / 效果图 / 无尺寸示意图**：按常见家具和门宽推算比例，注明「按常见尺寸推算，实际可能有偏差」。
4. **完全无法识别**（文件损坏、空白、与户型无关、图片看不清）：**不要写 `plan.json`**，在回复里说明原因和缺失信息，服务端会返回错误。
5. 多页 PDF：说明使用了第几页；其余页与户型无关就忽略。

## 5. 输出

1. 请求指明所有原图均已随消息附上时，读取这些图像并直接回复一个完整 JSON 对象。在顶层增加 `explanation` 字符串。无需打开或写入文件。
2. 需要读取本地文件时，把结构字段和 `furniture` 写入当前工作目录的 **`plan.json`**（UTF-8，能被 `JSON.parse` 直接读取）。保持上传文件原样，回复中文摘要。
3. 中文摘要不超过 300 字，其中必须包含标定结论：采用的总尺寸与量测面、尺寸链最大偏差、弧段数量与半径、飘窗房间数、估算项清单；另说明房间、总面积、家具和构件数量、文件格式或页码，以及尺寸、朝向或分类采用的近似处理。
4. `explanation` 与中文摘要口径一致，不得出现与 `dims` / `source` 矛盾的描述（例如把估算写成实测）。

如果文件完全无法识别，按 §4 第 4 条处理：说明原因，不要写 `plan.json`。
