# 户型图纸解析（plan-import）

工作目录里有用户上传的户型资料：图片（JPG / PNG / WebP / 截图 / 扫描件）、PDF（多页时找含户型的那一页）、CAD 导出（DXF / DWG 转出的图片、打印稿或文本）、以及可能已经是 Plan 结构的 JSON、纯文字说明等，**格式不固定**。

读取请求附带的图像和工作目录中的资料，自行识别文件格式。识别户型、家具和图纸上明确画出的构件，输出结构字段和 `furniture`。

图纸标定、结构读取和家具识别使用同一份原图。需要放大检查时可读取本地文件。

## 1. 坐标与单位

- 全部长度单位是 **mm**。
- 2D 坐标系：x 向右，y **向下**；原点可自选，通常取户型左上角 `(0, 0)`。
- 对平面图先建立图面坐标到毫米的映射。优先取界线端点清楚的总尺寸或长尺寸标定，用同方向的分段尺寸交叉核对。有可读取的矢量线时，沿标注的尺寸界线追踪其引用的几何。图面有横纵拉伸时分别标定 x 和 y。墙体、门窗、房间及家具沿用同一原点、比例和取向。
- 直墙、直窗、门和推拉门使用轴对齐矩形。斜直墙可用矩形近似，并在说明里注明。弧墙、弧形窗和房间圆角使用下面的圆弧字段。

### 外轮廓、分段尺寸链和房间净尺寸

1. 沿图纸中的外墙、外窗和转折追踪建筑外轮廓。沿每条尺寸线的两侧界线回到实际起止点，判断它们对应外沿、内沿、墙轴线、洞口边或退台转折。建筑外包尺寸取对应围护结构外沿。若总尺寸标到轴线，依据可读墙厚及轴线与墙面的关系换算到对应外沿。若界线明确标到露台等室外轮廓的两端，室外区域的对应边坐标直接使用标注的跨度，无需加墙厚。Plan 的 `bounds` 只表示画布范围，可含留白。
2. 按 x、y 方向分别读取总尺寸、分段和子尺寸。同方向且共用首尾界线的连续分段才与总值比较，同一跨度的替代标注与子段只计一次。按相邻界线的已读距离累计坐标，保留每个转折、洞口和墙面的归属。遇到不同端点或局部截面的标注，分别定位并核对，墙厚只在实际跨过墙体的区间计入。
3. 逐房沿标注界线定位净尺寸所指的两条内侧完成面。图纸未区分装饰层时采用能确认的房间内边界。用 `rooms[].poly` 表达对应内边界，同时使 `walls`、`wins`、`doors` 和 `slides` 对齐原图。矩形房间核对内边界间的净开间和净进深。遇到 L 形、退台或弧形房间，保留凹口、转折和圆弧，以标注所在的具体截面为准，按实际多边形建模。例如，确认为从外沿到外沿的 6200 mm 尺寸链依次为 240、2720、120、2880、240 mm，则以左外沿为 x=0 时，两间净宽分别由 x=240 至 2960 和 x=3080 至 5960 的内边界得到。
4. 输出前用最终几何重新量算外包、分段及净尺寸，核对与所引用的图面标注是否一致。若已读数值互相矛盾或界线模糊，保留有清晰依据的几何，其余按已标定的图面合理近似，在中文摘要中注明需要人工核对的部位和依据。沿用 Plan V1 字段，将已确认的尺寸写进墙面、房间边界和洞口坐标。摘要用来区分按标注、按比例量算和待复核的尺寸。

## 2. Plan 结构

```json
{
  "version": 1,
  "name": "方案名称",
  "bounds": { "x": -240, "y": -240, "w": 10240, "h": 8240 },
  "walls": [[0, -240, 8240, 0, "e"]],
  "wins": [[1000, 0, 2200, 240]],
  "doors": [{ "name": "入户门", "rect": [4580, 8310, 4820, 9200], "h": [4820, 9200], "c": [0, -1], "o": [1, 0], "len": 890, "entry": true }],
  "slides": [{ "rect": [10270, 7400, 10510, 9770], "v": true }],
  "rooms": [{ "id": "living", "name": "客厅", "poly": [[0, 0], [4000, 0], [4000, 3000], [0, 3000]], "mat": "tile800", "at": [2000, 1500] }],
  "materials": { "tile800": { "name": "800 地砖", "price": 220, "sw": "#ebe6dc" } },
  "furniture": [{ "type": "sofa", "name": "双人沙发", "cx": 1250, "cy": 1500, "w": 1680, "d": 780, "rot": 270, "color": "#e8e4dd" }]
}
```

### 字段说明

- `bounds`：2D 世界范围（含墙厚），四周可留 240mm 余量。
- `walls`：`[x0, y0, x1, y1, kind]`，坐标**已含墙厚**（矩形就是墙体本身，不是中心线）。`kind`：`e` 外墙、`b` 承重墙、`n` 非承重墙、`low` 矮墙。
- `wins`：窗洞矩形 `[x0, y0, x1, y1]`，贴在墙上，不要跨出墙体外。
- 圆弧墙段和圆弧窗段在相应的 `walls` 或 `wins` 数组中使用对象，例如 `{"from":[6000,1000],"to":[7000,2000],"sweep":90,"thickness":240}`。
  - `from` 和 `to` 是圆弧**中心线**的起止点（mm），`thickness` 是截面总厚度（mm）。圆弧墙还可设 `kind` 和 `height`（mm）。
  - `sweep` 是从起点到终点扫过的有符号圆心角，绝对值为 0.5–180 度。在 y 向下的坐标里，顺时针为正，逆时针为负；交换起点和终点时反转符号。示例从横向接线向右延伸并转向下方。
  - 识别原图中直线结束、开始弯曲的位置，用两侧直线与圆弧的切点确定起止点。透明玻璃连续转角归入 `wins`。圆弧使用独立一段，与相邻直段在端点衔接，避免重复铺设墙体、窗洞或阶梯状矩形。
  - 圆角窗外缘、中心线、内缘共用圆心。沿平行细线定位内外缘，再求中心线；同一玻璃带只输出一条窗弧，厚度取内外缘径向距离。相邻直窗延伸到实际切点，室内房间轮廓沿玻璃内缘收口。
- `doors`：平开门（门洞 + 门扇）。
  - `rect`：门洞矩形 `[x0, y0, x1, y1]`，落在墙体上。
  - `h`：**铰点坐标** `[x, y]`，取门洞矩形的一个角。
  - `c`：**关门时门扇的方向单位向量**，从铰点指向关门状态的门扇末端；必须沿门洞长边，取值 `[1,0]` `[-1,0]` `[0,1]` `[0,-1]`。
  - `o`：**开门方向单位向量**，从铰点指向开门状态的门扇末端；与 `c` 垂直，取值同上（`c·o = 0`）。
  - `len`：门扇长度（mm），等于门洞长边（例如 800–900）；`rect` 的短边只是墙厚（如 240），不要拿短边当 `len`。
  - 入户门加 `"entry": true`；一户型最多一个。
- `slides`：推拉门。`rect` 门洞矩形；`v` 为 `true` 表示门洞**竖向**（长边沿 y，门扇沿 y 方向推拉），`false` 表示横向。
- `rooms`：房间多边形。
  - `poly`：顶点数组 `[[x,y], ...]`，**至少 3 个点**，首尾**不重复**，不要自交；同一房间的顶点按**视觉顺时针**排列（y 向下时鞋带公式面积为正）。
  - `arcs` 可用于有圆角的房间、阳台或露台。弧段登记为 `{"edge":i,"sweep":90}`，从 `poly[i]` 到 `poly[(i+1)%poly.length]`，每条边最多一条弧。不需要在 `poly` 里放中间采样点。室内轮廓使用墙或玻璃内缘的切点，室外相邻地面使用外缘的切点，室内外轮廓和墙窗中心线共用圆心。
  - `id`：英文小写、不重复；`name`：中文。
  - `mat`：`materials` 里的键；`at` 是标签位置，可省略（服务端取质心）。
  - 确认是室外露台、花园或平台时设 `"outdoor":true`，套内使用面积不计时另加 `"counted":false`。露台绿化、铺地填充的外沿圆角只写入室外区域轮廓。
  - 只有图纸画出独立窗台轮廓、台面分界、剖面或明确标注时，才把飘窗台作为独立区域。飘窗区沿实际玻璃内缘和开口的内侧交界画 `poly`，加 `"counted":false` 和 `"bay":{"roomId":"master","openingEdges":[0]}`。`roomId` 是相邻室内房间 id，`openingEdges` 是飘窗多边形真正敞开朝向室内的边号。窗台高度有标高依据时才填 `sillHeight`（mm）。弧形外窗直接围出平齐的房间时，室内房间边界沿玻璃内缘留弧。
  - **至少要有 1 个房间**，否则页面会拒绝加载。
- `materials`：键名尽量用固定 8 种：`wood`、`walnut`、`tile800`、`tile600`、`marble`、`antislip`、`terrazzo`、`carpet`；每项 `{ name, price, sw }`（`sw` 是色块 `#rrggbb`，`price` 是每平米单价，认不出就给合理默认）。
- `furniture`：画出且可识别的家具、家电、厨卫设备及构件，一件物体一条。每项含 `type`、`name`、`cx`、`cy`、`w`、`d`、`rot`，可选 `color`（`#rrggbb`）。没有可识别的家具或构件时用 `[]`。
  - `cx` 和 `cy` 是家具自身外轮廓的中心坐标，`w` 和 `d` 是家具自身横向和前后方向的实际尺寸。用图中的独立轮廓按比例量算，排除家具投影、尺寸文字、门扇开启线和通行区。
  - `rot` 是平面内顺时针角度，范围为 `0 <= rot < 360`，斜摆时可用小数。桌子的宽度轴在图中竖放时按 `90` 摆放，`w` 仍是物体本身沿宽度轴的尺寸。家具以靠背、床头、水箱或龙头靠墙的一侧为后，正面在 `0` 度时朝图下、`90` 度朝左、`180` 度朝上、`270` 度朝右。例如，桌左侧面向桌子的餐椅用 `270`，右侧用 `90`；茶几下方朝它的沙发用 `180`。先按家具自身轴测量 `w`、`d`，再应用角度。
  - `cornersofa` 的转角侧用 `handedness` 表达。先按原图确定主排靠背和 `rot`，再换回 `rot: 0` 的局部视角。主排靠背在上时，从图面看向下延伸的一段在左（局部 `-x`）写 `"left"`，在右（局部 `+x`）写 `"right"`。零度、靠背在图上、短边向图右下延伸的沙发写 `{"rot":0,"handedness":"right"}`。看到完整轮廓时明确填写，旧数据省略时按左转角绘制。
  - `coffeetable` 和 `sidetable` 可用 `topShape` 表达台面轮廓，矩形用 `"rect"`，圆形用 `"round"`，椭圆用 `"oval"`。根据台面实线判断，圆形的 `w`、`d` 用同一测得直径，椭圆的 `w`、`d` 分别量两条全轴，长方形条几按四条直边量算。旧数据省略时沿用各类型的默认形状。
  - 茶几、边几的 `height` 是台面离地高度（200–800 mm），仅在图纸提供标高或图示清楚表达高低套叠时填写。套叠组合的两张桌子可保留原图中的平面重叠，并用不同 `height` 区分。图中无标高时，将高度标为建模估算。

## 3. 识别规则

1. 优先使用界线明确的图纸标注，未标注的局部按已标定原图量算。整图缺少可靠标注时，可参考常见门宽 800–900 mm、600 地砖或墙厚估算比例，并在说明里写清假设。
2. 墙厚默认：外墙 240 mm、内墙 120 mm、矮墙 100 mm。图纸有标注时以标注为准。
3. 房间 id 用英文小写（`living`、`master`、`kitchen`、`bath1`…），不要重复。
4. 房间名称用中文（客厅、主卧、厨房…）。
5. 门洞、窗洞要落在围护结构上，两侧的实墙在洞口边缘断开。保留连贯的玻璃转角和相邻地面的圆弧轮廓；半径根据图纸标注或原图比例量算。
6. 缺少的信息给**合理默认值**（门朝内开、房间地面用 `tile800`、无窗等），不要留空字段，也不要编造不存在的房间。
7. 材料无法判断时：卧室/客厅用 `wood`，厨卫/阳台用 `tile800` 或 `antislip`，并在说明里注明。
8. 若上传的是 Plan JSON 或带 `plan` 和 `state` 的项目 JSON，规整 Plan（补 `id` / `name` / `mat` / `at`、修正矩形顺序），保留已有家具和构件的坐标、尺寸、角度、`handedness`、`topShape`、`height` 及 `parts`。项目 JSON 的家具和构件来自 `state.furniture`，输出时放在和结构字段同一级的 `furniture`。

### 弧形围护逐段核对

沿室内外分界从图的左上起顺时针走一圈，再检查花园、天井等内凹边界。逐个核对直段与弧段接缝，保留可见圆弧。与相邻直窗连续的多条细线通常是玻璃，延续实填墙体的曲线按实墙处理。按各自用途处理铺地、绿化、家具、门扇摆弧。对每处能确认的连续玻璃转角，检查 `wins` 中有正确朝向的弧段，并使相邻室内房间和室外区域沿各自实际边沿配合。能确认弧形窗但看不到台阶、台面或剖面时，保留弧形平面，在摘要中列出窗台性质和高度待核实。

若消息附有原生 CAD 曲线，使用图元确定端点、圆心、半径、角度和邻接关系。先核实构件用途，再把 CAD 坐标变换为 Plan 毫米坐标。CAD 的 Y 轴向上，变为 Plan 的 Y 轴向下时角度反号。单位未声明时依据图纸明确读数标定。若消息附有图片像素拐角候选，`corner` 是两条直段延长后的虚拟交点，真实弧段接在 `horizontalTangent` 和 `verticalTangent`。沿这两个切点核对原图，按标定比例和边线厚度定位模型中心线。

### 家具识别

逐个房间检查原图。餐桌、每把画出的餐椅、边几、橱柜台面、台面上清楚可辨的水槽或灶具，各按轮廓单独记录。保留原图明确画出的组合叠放关系，例如茶几在地毯上。多个资料画出同一件物体时只记录一次。固定柜体可以按所在房间和轮廓匹配家具库中的对应柜类。无法区分是物体、门窗符号还是注释的图形可省略。

优先采用家具明确标注的尺寸，其余按标定比例从图面量算。选用对应的家具库类型，尺寸采用量算结果。若轮廓局部缺失，以能识别的轮廓和同图同类物体估算，并在中文说明中指出近似项。若原图只画了空房间，输出空数组。

输出前逐个比对局部原图和家具组合。放大客餐厅等布置密集的区域，核对以下关系，同时沿用整张图纸的坐标标定。

- 用最近的墙、窗、柜体等作参照，检查家具中心在原图的相对位置、家具前后方向、成组家具的间距和数量。例如，转角沙发的短段应位于原图指定的一侧，茶几在沙发两段围出的空区，餐椅逐把对照餐桌和靠背方向。
- 按看得见的外轮廓核对 L 形、圆形、椭圆和矩形，通过结构字段表达。模型库确实缺少对应轮廓时，可按下节建模。只把具有独立实物轮廓的符号识别成家具。
- 检查实物轮廓与墙体和家具的重叠，L 形沙发只检查两段实体占地。保留有原图依据的套叠圆桌、茶几压地毯、台面嵌装和餐椅收进餐桌等关系。看不清的形状或关系写进中文摘要，供用户在打开方案前核对。

家具库类型如下。

- 卧室：`bed` 床、`crib` 婴儿床、`nightstand` 床头柜、`wardrobe` 衣柜、`dresser` 梳妆台、`desk` 书桌、`chair` 椅子、`bookshelf` 书架、`baycushion` 飘窗垫。
- 客厅：`sofa` 直排沙发、`cornersofa` 转角沙发、`armchair` 单人沙发或扶手椅、`beanbag` 懒人沙发、`coffeetable` 茶几、`sidetable` 边几、`tvstand` 电视柜、`rug` 地毯、`shoecab` 鞋柜或玄关柜、`floorlamp` 落地灯、`plant` 绿植。
- 餐厨：`table` 桌、`roundtable` 圆桌、`island` 岛台、`barstool` 吧椅、`counter` 橱柜台面、`stove` 灶具、`ksink` 水槽、`fridge` 冰箱、`cabinet` 储物柜或餐边柜。
- 卫浴：`toilet` 马桶、`vanity` 浴室柜或洗手台、`shower` 淋浴房、`bathtub` 浴缸、`washer` 洗衣机、`waterheater` 热水器。
- 家电：`tv` 电视、`aircon` 柜机空调、`acwall` 挂机空调、`dishwasher` 洗碗机、`ovencol` 蒸烤箱高柜、`dryer` 烘干机、`purifier` 空气净化器。
- 书房与休闲：`officechair` 办公椅、`piano` 钢琴、`treadmill` 跑步机。

### 图纸构件和家具库缺项

楼梯、端景、壁龛、异形展示柜等有清晰图示或标注却无对应家具库模型的物体，用 `type: "component"` 输出。按原图整体轮廓确定 `cx,cy,w,d,rot`，通过 `parts` 描述占地和立体形状。一件构件用一条记录，组成部分留在同一个 `parts` 中。

- 每个部件是 `{ "shape": "box", "x": 0, "z": 0, "w": 1, "d": 1, "y": 0, "h": 800 }`。其中 `x,z` 是相对构件中心的局部横向和纵向比例，范围 `[-0.5,0.5]`，`w,d` 是占整体宽深的比例，范围 `(0,1]`。`y` 为底面标高，`h` 为高度，单位均为 mm。可选 `rot` 为部件自身的顺时针角度，可选 `color` 为色值。每件最多 48 个部件。
- `box` 表示板、柜、台和平台等矩形体。`cylinder` 表示圆形或椭圆柱体。`stairs` 表示平行踏步线的直梯段，另填整数 `steps`（1–32）。`rot: 0` 时沿局部 `-z` 到 `+z` 上行。
- `winder` 表示围绕内角转向的扇形踏步。每级由 `pivot` 与外边界上相邻两个 `edges` 点围成。点坐标都相对这个部件自己的宽深归一化，范围 `[-0.5,0.5]`。沿上升方向排列外边界点，可沿矩形外边的拐角转折，`edges` 有 `steps + 1` 个点，`steps` 为 2–32。比如内角在上边中央、从左到右折返四级时，`pivot: [0,-0.5]`，`edges: [[-0.5,-0.5],[-0.5,0.5],[0,0.5],[0.5,0.5],[0.5,-0.5]]`。
- 通过踏步线、箭头和平台标记判定楼梯走向。细看转角：如果多条斜线向同一内角汇聚，应按各斜线对应的外边界端点创建 `winder`。水平平台用 `box`，等距平行踏步用 `stairs`。各梯段的 `h` 为该段高差，后段从前段顶点标高继续，段间在平面上衔接。楼梯间仍可另有房间轮廓。
- 端景从文字标注和图形确认。用图中轮廓还原占地，以板、台、陈设等组合表达。一处构件的高度、材质或内部构造无法从原图读取时，在说明中注明按估算建模。

## 4. 识别失败 / 不完整时的兜底

按以下顺序处理，不要硬编造：

1. **能认出户型轮廓和房间**：按图输出完整 Plan，把按图估算的圆弧尺寸、比例或其他近似写进说明。
2. **只能认出部分**（例如只有外墙轮廓、只有房间名、只有尺寸标注）：输出**最合理的完整 Plan**（至少 1 个房间，墙 / 地面给默认值），并在说明里逐条列出「哪些是推测」。
3. **是照片 / 效果图 / 无尺寸示意图**：按常见家具和门宽推算比例，注明「按常见尺寸推算，实际可能有偏差」。
4. **完全无法识别**（文件损坏、空白、与户型无关、图片看不清）：**不要写 `plan.json`**，在回复里说明原因和缺失信息，服务端会返回错误。
5. 多页 PDF：说明使用了第几页；其余页与户型无关就忽略。
